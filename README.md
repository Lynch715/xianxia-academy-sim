# 修仙学院模拟器 · 云霄仙院

单 HTML 文件的文字模拟经营 RPG。所有数值与因果由本地 JS 引擎裁决；LLM 扮演每一个人物跟你对话，再把裁决结果写成小说。**没有 API Key 时游戏完整可玩**（内置模板文本），填入 Key 后叙事升级为 2000 字级动态生成。

## 快速开始

```bash
node build.js          # 拼接 src/ → index.html
```

有 Key 时人物会真的开口跟你说话（见下方「对话场」），没 Key 时是内置文本的选项游戏。

然后双击 `index.html` 即可游玩。无需服务器，无需联网。

在线版：推到 GitHub 后由 Actions 自动部署到 Pages（见下方「部署」）。

想接入模型：进游戏后点右上角「设置」，选服务商、填 API 密钥。密钥只存在浏览器 localStorage，代码里没有任何上报逻辑。

各家的默认模型集中写在 `src/llm/adapter.js` 的 `PROVIDERS` 里，每家两个：`model` 平时叙事用，`modelPro` 给要紧场景（DeepSeek 对应 `deepseek-v4-flash` 和 `deepseek-v4-pro`）。换模型改那一处就够，UI 不再重复一份。

**哪些算要紧场景**：心魔关、结局尾声，以及事件本身标了 `important` 的（突破、暗线揭晓这类）。走的是 `call(..., { important: true })`，在 `body()` 里换成 `modelImportant`。设置面板中「重要场景使用高级模型」那个勾控制它，勾掉就全程用平常模型。

**改默认值救不了老玩家。** `load()` 是拿存档覆盖默认值的，存档里那份旧值永远赢——所以调默认值必须配一次性迁移，靠 `cfgVersion` 控制只补一次，之后玩家自己清空了就是清空了。已下线的模型名列在 `LLM.RETIRED` 里同理，不然浏览器里存着 `deepseek-chat` 的人一开局就是 400，而报错只说"模型不存在"，很难想到是旧配置。

DeepSeek V4 的思考模式默认开着，适配层会显式关掉：写小说不需要它先推理一遍，而且思考模式下 `temperature` 会被忽略（叙事变平淡），思维链走的是 `reasoning_content` 字段而非 `content`，流式输出会表现成"转半天没字、然后突然一大段"。

## 测试

```bash
node test/headless.js 60            # 引擎对拍：60 周推演 + 全部断言
node test/headless.js 240 3333      # 完整五年长跑，第二个参数是随机种子
node test/balance.js                # 平衡对照：随机乱点 vs 谨慎游玩
NODE_PATH=/tmp/node_modules node test/dom.js   # jsdom 界面冒烟测试（需 jsdom）
NODE_PATH=/tmp/node_modules node test/viewport.js  # 移动端：八种机型 + 安全区 + 图标
node test/render.js                 # 真 Chromium 量排版（需 playwright，没装则自动跳过）
```

`headless.js` 校验数值不越界、随机流可复现、存档往返一致、白名单能挡住恶意模型输出、prompt 规模受控，并跑通三种秘境、三类大型活动、暗线推论、动态主角绑定与五条结局触发路径。换种子可以验证不同剧本走向。

`balance.js` 跑六个种子 × 两种玩法，比对心魔、境界、名次、结局。它不校验对错，只校验"用心玩有没有回报"——如果两种玩法结果差不多，说明选项没有分量。当前实测：随机玩法平均心魔 91、六局里两局被劝退；谨慎玩法平均心魔 27、六局全部善终且境界更高。

`dom.js` 在 jsdom 里走一遍真实 UI：标题页 → 角色创建 → 主界面 → 日程 → 推演 → 秘境探索 → 七院大比 → 春猎 → 心魔关 → 暗线推论 → 教习弟子面板与研究 → 院主议事表决 → 结局页，共 27 项。

`render.js` 用真的 Chromium 量盒子。jsdom 完全不排版，`viewport.js` 只能验"规则在不在"，而三个真实存在过的 bug 都不是规则缺失：状态页被灵动岛压住第一行、`.layout.tab-main` 因为类名没输出而永不匹配、底部空出一截。这些只有真排版才量得出来。它检查内容上沿是否落在安全区外（用注入的 `--sa-*` 假值模拟，真机上 `env()` 填进同一处）、有无横向溢出、滚到底后末行与标签栏的距离，并在同一个页面里切视口验证转屏确实触发了重排。没装 playwright 时自动跳过，不阻塞。

`viewport.js` 管移动端。jsdom 不做真实排版，所以它分两头查：一头是**静态断言**——`viewport-fit=cover` 在不在、四个方向的安全区变量有没有被真正用上、hover 有没有被 `(hover:hover)` 包住、apple-touch-icon 是不是不带透明通道的方图、manifest 里的图标路径是否都存在；另一头是**运行时**——在八种机型尺寸下渲染，断言横屏手机判定、`.layout` 的 `tab-*` 类、三个标签的文案（竖屏「状态/叙事/安排」，横屏「状态/专注/日程」），再反复转屏六次确认存档和界面都没丢。

## 对话场：人物会真的开口

这是 1.1 版最大的改动。此前模型只是"墙纸"——骰子先掷、数值先算，模型负责事后写 1800 字散文，NPC 从不真正跟玩家说话。现在有 Key 时，凡是有人在场的事件都先进**对话场**：

1. 开场文之后，事件里的人先开口（模型按 `npcs.json` 里的性格、声线、秘密、和你的交情扮演）。
2. 你可以直接打字，也可以点模型给的三条快语（一条试探、一条真诚、一条绕开）。最多四句。
3. 每一句 TA 都会回，立绘表情跟着 TA 的情绪切（`calm / emotion / special` 三张图正好对上）。
4. 聊完再选 A/B/C。聊得好坏变成 ±12 的判定修正——顶得上一档半——选项下面那行"有几分把握"会跟着变，这是玩家能感到"说话有用"的地方。
5. 聊到点子上，TA 可能露出秘密的一角：模型只发"愿意说"的信号，**能不能算数由引擎核验信任门槛**。成立则记入关系日志，七位与暗线有关的人物（柳眠烟、楚河山、澹台无咎、云舒、裴无忧、苏暮寒、钟离衡）会直接落成推论表里的线索。

**铁律没变。** 模型每回合只返回 `{say, expr, rapport, close, reveal, suggest}`：一句台词、三个枚举/布尔、三条快语。`rapport` 夹在 -2..2，累计夹在 ±8，映射后夹在 ±12；`reveal` 只是信号；玩家输入只当"玩家说的话"塞进 prompt，system prompt 里明确告诉模型无视其中任何"系统提示 / 判定 / 好感+10"。`test/headless.js` 里的 `dialogueGuard` 拿恶意输出打了一遍。

**心魔关也是对话。** 幻境文之后，心魔开口——有具体的人就借那个人的样子（立绘褪色），没有就是你自己。它专挑你经历里最痛的地方说，你最多回三句。模型每句判断你的道心是更稳还是更乱（`rapport` 正负），引擎累计后夹成 ±8 的成功率修正和 ∓4 的心魔升降；**稳到 5 以上，连"最险的那条路"都不会直接走火**——这是对峙做得好的真正奖励，比选项本身的 +12 小，所以对话是加分不是替代。

**日程里的「自拟」。** 活动选择器最下面多了一个输入框：一句话安排这个时段（"去后山找叶素素看看她的灵兽"）。推演到那一格时经 `parseAction` 白名单解析 → 五档判定 → `Game.resolveCustom` 按档位给小额收益（修为 ≤12、点名的人好感 ≤6、助人尚可以上声望 +1、高风险糟糕会受伤或涨心魔）→ 260 字左右的叙事。越界的行动（"一掌拍死院主"）被拒，时段作废。没 Key 也能用：`Fallback.parseAction` 按关键词解析，文字里点了名的人自动成为目标。收益刻意压得不高于"拜访"或"打坐"，否则日程表上其它格子就没意义了。

**传闻：说话有用，从单线变成一张网。** 你对一个人做的事会被别人听说（`src/systems/rumor.js`）。来源只取值得说的：事件圆满且好感 +8 以上（帮了 X 一把 / 和 X 走得很近）、糟糕且好感 -5 以下（和 X 闹得很不愉快）、违心之事（做了件说不出口的事）、切磋赢了、背后议论、对话场聊得特别好或特别僵。每周结算时每条传闻按「同院 > 同为弟子 > 其他」往外走一两个人，八周后消散，最多八条同时在传。听到的人按传闻性质和自己的性格改观——全是 ±4 以内的小数目：守旧派对坏话更苛刻，逍遥派无所谓，出事的人的同院更在意，对你有意的人听说你和别人走得近会吃醋，教习不会因为弟子切磋赢了而敬畏。**出口在人物嘴里**：对话场和传音的 prompt 里带上「TA 听人说起过的事」，人物会自己提起「听说你……」；关系卡上也写着「TA 听说」。**反制**：坏话传开了，去找听过的人好好谈一次（对话 rapport ≥ 3），那条传闻对 TA 的影响退还一半，只退一次。传闻文本是模板，不带任何人的秘密。

平衡对照实测（`test/balance.js`）：谨慎玩法一局起 146 条传闻、累计好感影响 +184；随机乱点起 113 条、累计 -239。同一套机制，用心玩是加分，乱玩是网住自己。

**传音符**：认识的人会主动找你。周末结算后按关系抽人（同窗更爱串门，关系紧张的很少来），模型用 TA 的口吻写一条不超过 60 字的短讯——约你做件具体的事、问你一个问题、或提醒你一件事。回话就是一段自由对话，聊完按 `deep_talk` 结算；不理会则 `ignore_long`，TA 会记得。每两周至多一条，一个 NPC 四周内不重复。

**叙事减肥**：普通事件从 1800 字降到 700，要紧场景（心魔关、暗线、圆满/糟糕）自动放大 1.6 倍。对话场已经把戏演过一遍，叙事只写"对话之后"，prompt 里明确要求不复述对话。老配置里还停在 1800 的会由 `cfgVersion: 3` 迁移一次，自己调过的不动。

**成本**：一回合对话约 1.5k token 进、150 出，比原来一段 1800 字叙事便宜；一个事件（开场 + 三句 + 叙事）总量与旧版一次叙事相当。

**当下要紧**：右栏那句"平常的一周"换成了一份倒计时——月考还有几周、照眼下势头大约在哪一档、哪件事还没了结、谁的传音没回、心魔到哪一级、灵石够不够。纯本地计算，不花 token。周末结算后也会在正文里出现一次。

**本地调试**：`node test/mock_llm.js` 起一个假的 OpenAI 兼容接口（8765 端口），设置里选"自定义中转"、地址填 `http://127.0.0.1:8765`、密钥随便填，就能不花钱把对话场、传音、叙事整条走通。它按 prompt 里的标记决定回什么，还会故意对"好感+100"这种注入翻脸。

## 进度不会丢

自动存档本来就在每次 `commit` 后节流 400ms 写一次；这一版补上了「玩家要走了」的那几个信号——`pagehide`、`beforeunload`、`visibilitychange`（切后台、锁屏）、`blur`，触发就立刻 `Save.flush()`：自动存档和玩家配置（含 API 密钥）一起落盘，不等节流。iOS 上 `pagehide` 是唯一靠得住的，其它几个都是兜底，另外每 30 秒还有一次定时冲刷。

**打开就是刚才那一幕。** 有自动存档时启动直接进游戏，不经过标题页。开新局、找回上一局、回标题页都在设置里。

**中途退出不重推。** 一周推到一半关掉页面，时段已经推过去了，存档里 `time.day/phase` 停在断点。重开后 `beginWeek` 看到 `flags._midWeek` 就把断点之前的格子跳掉，按钮变成「接着推演本周（上次停在周三·午）」。不做这个，一周会被重复推一遍，时间凭空多走 21 个时段。没来得及选的那个事件会掉——它还没进 `seen` 和冷却，之后还会再来。

**误点「入院」找得回来。** 开新局之前，当前局先挪到 `xxxy_save_prev`；标题页和设置里都有「找回上一局」，两边对调，谁也不丢。结局页的「重来」同样先备份。有存档时标题页的主键是「继续」，「入院」要确认。

**密钥填了就存。** 设置弹窗里任何一次输入 300ms 后自动写入，不必点「完成」——手机上点一下蒙层、往下一滑，弹窗就没了，以前密钥也跟着没了。

`test/headless.js` 的 `persistence` 覆盖：中途退出读档续推恰好 21 个时段、开新局备份、对调两次回到原局、flush 立刻落盘。

## 三条铁律

**一、LLM 不返回数值。** 它的输出只会被当作字符串塞进 UI。玩家自定义行动的解析结果经过 `LLM.validateIntent` 白名单校验——属性键必须在当前身份的属性集里，难度夹到 [10,90]，reason 夹到 [-15,+20]，未知 NPC 一律丢弃。这是防 prompt injection 刷数值的唯一防线。

**二、commit 在叙事之前。** 网络断在叙事一半时，状态已经落盘了。叙事失败只影响表现，重试即可，不会出现「文字说成功了但数值没加」。

**三、上下文规模恒定。** 状态快照全量 + 最近 3 回合 facts + 滚动摘要（每 8 回合压一次）。实测单次 prompt 约 1450 token，与游戏进度无关——玩到第 240 周和第 1 周一样大。

## 几个容易踩的坑

**`conditions.minWeek` 是周，不是时段。** `absoluteTurn` 记的是时段数（一周 21 个），早期版本拿它当门槛，结果本该在第 80 周出现的诬陷事件在第 6 周就跳了出来，随机对拍八个种子里有三个在开局二十周内就被劝退。新事件一律用 `minWeek`。

**系统方法不要信传进来的 `s`。** UI 的事件回调会把 state 对象闭包进去，而读档、换存档都会替换 `G.State.current`。闭包握着旧对象时，`commit` 写的是新对象、`map` 读的是旧对象，表现为"点了按钮，数值纹丝不动"。`Faculty` 与 `Governance` 的对外方法一律在开头 `s = G.State.current`。

**选项容器挂在 `narrWrap` 上，`narr.clear()` 清不掉。** 不显式 `clearOptions()` 的话，上一轮的"推演本周"会留在屏幕上，而且排在新选项前面，先被点到。

**弹窗正文里也全是 `.btn-row`。** 手机上把操作键做成吸底是对的，但选择器 `.modal .btn-row` 会把正文里每个分类的按钮行一起吸住，往下滚时旧的几行会层层糊在屏幕上。吸底规则一定要挂在专用类 `.modal-actions` 上。

**弹出选择器要自己关。** `Theme.modal` 只帮你关底部那排操作键；正文里的按钮点完得显式 `close()`。忘了的话数据其实已经写进去了，屏幕上却还是那张选择表，看着像点了没反应。

**`cooldown` 也是周。** 和 `minWeek` 同一个坑：`s.events.cooldowns` 存的是时段，写入时要 ×21。早期版本直接当时段用，`cooldown: 40` 实际只隔两周就又跳出来，结果一局能刷出三十部著述。修完之后原来那批数值又显得太长（40 周意味着一局最多触发六次），统一按 ÷3 缩回，现在事件密度约每周一件。

## 手机与主屏

**两套布局，不是一套缩放。** 竖屏是单栏 + 底部三键标签栏（状态／叙事／安排），一次专心看一屏。横屏手机高度只剩 390 上下，底部标签栏要吃掉六分之一的屏，所以横屏换成**左侧竖排导轨**，主栏常驻、侧栏并排，中间那个键的含义也随之从「看叙事」变成「专注」——按下去收起侧栏，整屏留给正文。

**转屏判定交给 `matchMedia`，用的是和 CSS 里逐字相同的那条查询。** 自己拿 `innerWidth > innerHeight && innerHeight <= 540` 算有两个毛病：iOS 在 `orientationchange` 触发时这两个值还是旧的；而且 JS 和 CSS 各算各的，改了断点就会对不上——CSS 已经换成横屏布局，JS 还以为在竖屏，标签文案和实际布局互相打架。现在监听 `mql.change`，浏览器判什么就跟什么，不可能不一致；`resize` 只作为地址栏收起、分屏拖动这类不翻方向但改尺寸场景的兜底。

**灵动岛与刘海。** `viewport-fit=cover` 打开安全区，四个方向各存成一个 CSS 变量（`--sa-top/right/bottom/left`），顶栏、三栏、导轨、标签栏、弹窗、创建页、结局页逐个让开。横屏时灵动岛跑到侧边，所以左右两侧同样要让——只让上下是最常见的疏漏。状态栏用 `black-translucent`，内容会顶到岛下面再由安全区推开，这样纸色背景是通铺的，不会在顶部留一条灰边。

**触屏细节。** 所有 hover 样式关在 `(hover:hover) and (pointer:fine)` 里，否则手机上点完会粘住高亮；选项热区加到 44px；关掉双击缩放延迟和点击高亮块；竖屏的弹窗改成从底部升起的抽屉（带把手，拇指够得到按钮），横屏保持居中但避开导轨。

**顶栏两行。** 手机上「灵元历3701年 · 九月 · 第1周 · 周一 · 晨」加五个键放不进一行，日期会折成五六行，把顶栏撑成半个屏——这是 1.1 审计时发现的最大问题。现在竖屏顶栏分两行：第一行是不带纪年的紧凑日期（`Time.compactLabel`，单行省略），第二行五个键等分。横屏主栏永远占宽列（`.col-main { order: 0 }`），否则「状态」分页会把主栏挤进 30vw。弹窗吸底那行操作键的底部内边距放在它自己身上而不是弹窗上：sticky 的定位矩形不含滚动容器的内边距，放在弹窗上正文会从操作键底下漏出来一截。`node test/audit_mobile.js` 会按三种机型把整条流程截一遍并量热区、溢出、遮挡、字号。

**禁止缩放。** 光写 `user-scalable=no` 没用——iOS 10 之后 Safari 出于无障碍考虑直接忽略它。真正拦住要堵四条路：CSS 的 `touch-action: pan-x pan-y` 只放行平移，`boot.js` 的 `lockZoom()` 拦掉 Safari 私有的 `gesture*` 事件、多指 `touchstart`、以及 300ms 内的第二次 tap。还有个容易漏的：输入框字号必须 ≥16px，否则 iOS 聚焦时会自动放大整页，而缩放又被禁了，页面就卡在放大状态回不去。

**加到主屏。** `manifest.webmanifest` + 12 个图标由 `python3 tools/make_icons.py` 生成，图案是宣纸底上的望仙峰剪影配一枚朱砂「霄」印。要注意两件事：iOS 的 `apple-touch-icon` 必须给**方图且不带透明通道**（系统自己加圆角，给圆角图会双重圆角，给透明图会变黑底）；安卓的 maskable 图标要把画面缩到内 78%，不然四角会被裁掉。加到主屏后 standalone 全屏运行，没有浏览器地址栏。

## 部署

`.github/workflows/pages.yml` 在每次推 `main` 时：跑全套测试 → 用 `src/` 重新构建 `index.html` → 部署到 Pages。

**在 CI 里重新构建是刻意的。** `index.html` 是构建产物，仓库里那份只是方便直接下载游玩。如果直接发布仓库里的版本，只要有人改了 `src/` 忘了跑 `build.js`，线上就会和源码对不上，而且很难发现。让 CI 生成，这种漂移不可能发生。

首次推送：

```bash
git remote add origin git@github.com:<你的用户名>/xianxia-academy-sim.git
git push -u origin main
```

然后到仓库 Settings → Pages，把 Source 设成 **GitHub Actions**（不是 Deploy from a branch）。之后每次推送自动发布。

`assets_raw/`（163 MB 的 PNG 母版）在 `.gitignore` 里，不进仓库；线上用的是 `assets/` 下 9 MB 的 WebP 成品。
