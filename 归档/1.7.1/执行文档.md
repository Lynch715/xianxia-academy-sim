# 《修仙学院模拟器》技术执行文档

版本 v1.0 · 2026-08-15

---

## 零、一句话定义

一个单 HTML 文件的文字模拟经营 RPG。**所有数值与因果由本地 JS 引擎裁决，LLM 只负责把裁决结果写成小说。** 没有 API Key 时游戏完整可玩（模板文本），填入 Key 后叙事升级为 2000 字级动态生成。

---

## 一、架构总纲

### 1.1 职责红线

这条线不能越，越了就会出现"玩家明明只有 120 灵石，模型却让他买了 300 灵石的丹药"这类崩坏。

**引擎负责（确定性，纯 JS，可单元测试）**

时间推进、属性增减、修为累积、突破概率计算、心魔值累积、关系四维数值、事件抽取与权重、考核评分与排名、经济收支、秘境探索判定、声望与阵营值、暗线触发条件、结局判定。所有随机数走**带种子的 PRNG**，存档可复现。

**LLM 负责（表现层，可失败可降级）**

把引擎输出的结构化结果渲染成叙事文本；解析玩家的自定义行动输入；为选项文案润色。**LLM 不得返回任何数值变更**，它的输出只会被当作字符串塞进 UI。

### 1.2 一次回合的完整数据流

```
玩家点击选项 / 输入自定义行动
        │
        ├─ 自定义行动 ─→ LLM.parseAction() ─→ {actionType, target, checkAttr, difficulty}
        │                   （失败则降级为"自由行动·通用判定"）
        ▼
   Engine.resolve(action, state)
        │  · 掷骰（seeded）
        │  · 五档判定 → grade
        │  · 计算 deltas（属性/关系/资源/心魔/声望）
        │  · 生成 facts[]（本回合确凿发生的事实，供叙事引用）
        │  · 生成 nextOptions[]（下一步可选项）
        ▼
   Engine.commit(deltas) ── 状态机唯一写入口，写完立刻存档
        ▼
   Renderer.render({state, scene, resolution, facts, options})
        │
        ├─ 有 Key → LLM.narrate() → 流式输出叙事
        └─ 无 Key → TemplateEngine.fill() → 模板文本
        ▼
        UI 更新（立绘 / 场景图 / 面板数值 / 选项区）
```

### 1.3 文件与模块结构

### 2.2 状态写入纪律

只有 `State.commit(deltas)` 能改 state。deltas 是一个数组：

```js
[
  { path: "cultivation.exp", op: "add", value: 27 },
  { path: "relations.npc_wenjiujiu.favor", op: "add", value: 8, clamp: [-100, 100] },
  { path: "resources.stone.low", op: "add", value: -30, min: 0 },
  { path: "events.seen", op: "push", value: "evt_017" }
]
```

commit 内部：校验 → 应用 → 触发派生计算（境界是否该升、关系阶段是否该变、暗线是否该解锁）→ 写存档 → 广播 UI 更新。

好处：所有数值变化有唯一审计点，调试时打开 `DEBUG_COMMIT=true` 就能看到完整变更流水。

## 三、核心系统实现规格

### 3.1 属性

三条路线属性键不同，UI 与判定表都按 `role` 分发。

| role | 键 | 初始点数 | 单项上限 |
|---|---|---|---|
| student | wu 悟性 / gen 根骨 / shen 神识 / ji 机缘 / xin 心境 / shi 世故 | 30 | 10 |
| teacher | xue 学识 / jiao 教化 / xiu 修为 / sheng 声望 / xin 心境 / shi 世故 | 50 | 15 |
| headmaster | wei 威望 / jue 决断 / ren 识人 / xiu 修为 / yuan 远见 / de 仁德 | 60 | 18 |

属性成长极慢：只通过特定事件、突破奖励、长期专注某类活动（累计 20 次同类活动 +1）获得。**不允许通过刷任务线性堆属性**，否则模拟经营的节奏就崩了。

### 3.2 判定引擎（五档制）

```js
function check({ attr, difficulty, modifiers, reasonBonus, luckAttr }) {
  const base = normalize(attr) * 0.5;      // attr(0-18) → 0-100 → 贡献 0-50
  const mod  = sum(modifiers);             // 关系/道具/环境/状态，clamp ±30
  const rsn  = reasonBonus;                // 选择合理性，-15 ~ +20（见下）
  const dif  = 50 - difficulty;            // difficulty 10-90 → +40 ~ -40
  const roll = rng.int(1, 100);
  const luck = (roll - 55) * 0.6;          // -32 ~ +27，运气影响约 1 个档位

  let score = base + mod + rsn + dif + luck;
  let grade = score >= 70 ? "perfect"
            : score >= 45 ? "good"
            : score >= 20 ? "plain"
            : score >= -5 ? "bad" : "terrible";

  // 奇遇与失手：保证任何局面都不是 100% 注定
  const critHi = 96 - Math.floor(luckAttr * 0.6);   // 机缘越高，奇遇门槛越低
  const critLo = 5;
  if (roll >= critHi) grade = bumpUp(grade);
  if (roll <= critLo) grade = bumpDown(grade);

  return grade;   // perfect圆满 / good尚可 / plain平淡 / bad不利 / terrible糟糕
}
```

`luckAttr` 对学生取"机缘"，教习取"世故"，院主取"远见"。奇遇机制让机缘 10 的角色有约 10% 概率跨档，这是原设计里"机缘影响随机事件中获得奇遇的概率"的落地点。

**平衡校验**：悟性 7、难度 30、选择合理（rsn +15）→ 得分 40~100，落在平淡至圆满；悟性 3、难度 70、选择鲁莽（rsn −10）→ 得分 −45~15，落在糟糕至不利，仅靠奇遇有约 5% 概率翻盘。属性主导、运气次之、选择合理性能顶约 1.4 个档位，符合设计意图。

**reasonBonus 是这套系统的灵魂。** 每个事件的每个选项在数据里预先标注 `reason` 值，代表"这个选择在当前情境下是否明智"。它由前置条件动态修正：比如"独自探查灵脉异动"这个选项，基础 reason = -10（鲁莽），但若玩家已从裴无忧处获得情报（flag 存在），reason 变为 +15。

这就实现了原设计里"选择本身的合理性同样重要"，而且完全确定性、可测试。

各档结果的 deltas 倍率：圆满 ×1.5 且额外触发正向支线；尚可 ×1.0；平淡 ×0.4；不利 ×-0.5；糟糕 ×-1.0 且可能挂载负面 flag 或心魔来源。

### 3.3 时间系统

一天三时段（晨/午/暮），一周七天 = 21 个时段。但**回合粒度是"周"**：玩家先排完一周日程，然后点"推演本周"，引擎按天推进，遇到事件就暂停等待玩家决策，处理完继续。这样既保留策略排程感，又不至于每个时段都点一次鼠标（一学年 = 40 周 = 840 次点击，太累）。

节奏基准：一学年 40 周（9 月至次年 6 月）+ 8 周游历期。五年学生路线约 240 个周回合。假设平均每周触发 1.5 个需要 LLM 叙事的事件，全程约 360 次 LLM 调用。这个数字决定了成本模型，见 §4.5。

月末自动结算：补贴发放、月考、关系自然衰减（长期未互动 -3/月）、心魔值微涨（若有未化解的负面 flag）。

### 3.4 修炼与突破

```
单次修炼收益 = floor(基础值 × 功法倍率 × 灵根系数 × 环境系数 × 心境系数)
基础值   = 4 + 悟性 × 1.2
灵根系数 = 天灵根1.8 单1.3(所修功法属性契合时1.5) 双1.15 三1.0 四0.85 五0.7 变异特判
环境系数 = 宿舍1.0 / 静修室1.2 / 灵脉节点1.3~2.0 / 秘境2.0~3.0
心境系数 = 1 - 心魔值/250        // 心魔 100 时降至 0.6
```

**校验**（对齐原设计稿的 UI 示例）：悟性 7、《青霄剑诀》黄级 ×1.5、单金灵根 1.3、静修室 ×1.2、心魔 12 → `(4+8.4) × 1.5 × 1.3 × 1.2 × 0.952 = 27.6` → **+27**，从 347/500 到满需 6 次修炼。与原稿一致。

`expMax` 按境界递增：练气每层 500 × (1 + 层数×0.15)，筑基 8000/阶，金丹 40000/阶。一学年约 40 周、每周投入 3-4 个时段修炼，对应练气期约需一学年——符合"水磨功夫"的节奏基调。

**突破流程是四段式，其中"心魔关"是唯一必须由 LLM 深度参与的环节：**

1. **准备**：选地点、是否服破障丹、是否请人护法（护法者好感 +，失败时可救援）
2. **入定**：引擎计算成功率，但**不告诉玩家精确数字**，只给模糊提示（"你感到丹田内的灵气比往日躁动"）
3. **心魔关**：引擎从 `demonSources` 中按权重抽 1-2 个来源，生成心魔关的**结构化骨架**（`{sourceType, targetNpc, coreConflict, correctChoiceTag}`），交给 LLM 写成一段幻境叙事 + 3 个选项。玩家选择后，引擎按 `correctChoiceTag` 匹配度判定。无 Key 时用预写的 12 套心魔关模板（按 sourceType × realm 分类）。
4. **结果**：大成功 / 成功 / 失败（修为回退 10-30%，休养 1-4 周）/ 走火入魔（触发危机事件链）

```
突破成功率 = 55 + 心境×3 + 丹药加成 + 环境加成 + 护法加成 - 心魔值×0.5 - 层数惩罚
层数惩罚 = 当前层数 × 2（练气）/ 阶数 × 8（筑基以上）
丹药：破障丹 +20 / 环境：静修室 +5、灵脉节点 +12 / 护法：护法者修为高于你一个大境界 +10
             （封顶 92%，地板 8%）
```

**校验**：心境 5、心魔 12、练气五层突破六层、无外物辅助 → `55 + 15 − 6 − 10 = 54%`。服破障丹 + 静修室 + 请沈惊澜护法 → 89%。裸冲有一半概率失败，肯投入就接近稳过——这个梯度能逼玩家去经营资源和人脉，而不是无脑点突破。

### 3.5 关系系统

四维（好感/信任/敬畏/羁绊）按原文档表推进。补充实现要点：

**阶段迁移是单向门 + 可退回**：好感掉到阈值以下不会自动退回阶段（已经是挚友不会因为一次争吵变回陌生人），但会挂 `strained` 状态，影响该 NPC 的事件权重和对话语气。只有极端事件（背叛、出卖）能触发阶段降级。

**NPC 自主生活**：每月月初，引擎为每个未在场 NPC 跑一次 `npcTick()`——按其性格与目标推进自己的修为、关系（NPC 之间也有关系网）、支线进度。玩家再见到他时能感知变化（"温酒酒的丹霞院排名从 88 升到了 31"）。这条是原设计"他们不是等待玩家触发的工具人"的落地方式，成本极低但体感差异巨大。

**NPC 主动性**：好感 ≥60 时，该 NPC 进入"主动事件池"，有权重触发主动搭话/送礼/邀约/吃醋事件。吃醋触发条件：玩家在最近 4 周内与另一 NPC 的好感增幅 > 20 且该 NPC 好感 ≥70。


**事件池规模目标：200+。** 分配建议：学业 30 / 社交 45 / 历练 30 / 危机 25 / 生活 25 / 感情 35（8 位可攻略角色各 4-5 个专属节点）/ 管理 20（教习院主专属）/ 暗线 20。

**抽取算法**：每周从满足 conditions 的池子里按 weight 加权抽 1-3 个。已 seen 的普通事件 weight ×0.15（不彻底移除，允许变体重现）。同一 NPC 的事件在 3 周内不重复触发。固定事件（学年节点）优先级最高，直接插入。

选项 E【自定义行动】永远存在，走 §4.2 的解析流程。

### 3.7 学业与考核

月考成绩 = 修为进境 30% + 术法掌握 25% + 课业完成 20% + 贡献点 15% + 品行 10%。全院 300 人排名用**正态分布模拟**：不真的模拟 299 个 NPC，而是生成一条随学年推进的分数分布曲线，玩家分数在曲线上取百分位。核心 NPC（沈惊澜等）的排名单独维护并强制插入合理位置。

末位 30 名连续两学期 → 劝退结局分支。

### 3.8 秘境探索

进入秘境切换为独立子界面，回合制推格子（不是真的网格，是"节点图"——每个秘境是一张有向图，8-20 个节点）。每回合选：前进 / 搜索 / 休整 / 用技能 / 撤退。灵力值和伤势是秘境内的限制资源，逼玩家做深入 vs 保命的取舍。

青霄试炼塔 12 层是线性图，每层考验类型固定（战斗/心境/知识/求生 循环）。灵墟是随机生成的分支图，每年重生成一次。

### 3.9 暗线状态机

四条暗线各是一个 `progress: 0-100` 的推进条 + 线索集合。触发条件按原文档。关键设计：**线索是可组合的**，玩家收集到特定线索组合时解锁"推论"（比如同时持有"钟离衡的密信"+"白鹿卿家族档案"时，可主动向楚河山质询，跳过 20 点进度）。这让暗线有解谜感而不是纯挂机。

暗线进度影响结局池：隐藏结局 18/19/20 需要对应暗线 progress ≥ 90。

### 3.10 结局判定

游戏在触发终局条件（毕业/身死/被逐/退位/超脱）时，跑 `ending.evaluate(state)`。所有 20 个结局有条件表达式，按优先级从高到低匹配，取第一个满足的。隐藏结局优先级最高，悲剧型次之（悲剧条件一般更硬），成就型最低（保底）。

匹配后展示：结局插画（云海日出/山门月色等复用场景图 + 滤镜）+ 结语文本 + 台词 + 一份**存档履历**（关键抉择时间线、最终关系网、达成的成就）。履历这块建议交给 LLM 生成一段 300 字的"院史评述"，是很好的收尾体验。

## 四、LLM 接口契约

### 4.1 适配器接口

```js
window.LLM = {
  configured: false,
  config: { provider, baseURL, apiKey, model, temperature, maxTokens },

  async narrate(payload, { onChunk }) -> string,   // 流式，返回完整叙事
  async parseAction(text, context) -> ActionIntent,
  async summarize(turns) -> string,
  async epilogue(state) -> string,

  test() -> Promise<boolean>                        // 设置页的"测试连接"
};
```

Provider 适配层统一成 OpenAI Chat Completions 格式（Anthropic / OpenAI / DeepSeek / 智谱 / 月之暗面 / 自建中转都兼容这个形状，只需换 baseURL + 少量 header 差异）。Key 存 `localStorage`，明确告知玩家"密钥仅存在你的浏览器，不经过任何服务器"。

### 4.2 parseAction 契约

玩家输入自由文本 → 模型必须返回**严格 JSON**（用 response_format / 或 prompt 强约束 + 解析失败重试 1 次 → 仍失败则降级）。

```json
{
  "intent": "sneak_follow",
  "summary": "偷偷跟踪裴无忧",
  "targets": ["npc_peiwuyou"],
  "check": { "attr": "shen", "difficulty": 60 },
  "reason": -5,
  "riskLevel": "medium",
  "violatesRules": false,
  "rejectReason": null
}
```

**引擎对返回值做白名单校验**：`attr` 必须在当前 role 的属性集里，`difficulty` clamp 到 [10, 90]，`reason` clamp 到 [-15, +20]，`targets` 必须是已知 NPC ID。任何越界值被夹紧或丢弃。这是防止玩家 prompt injection 刷数值的关键防线。

**越界行为拦截**：如果玩家输入的行为超出境界/身份（"我一掌击杀院主"），模型置 `violatesRules: true` 并给 `rejectReason`，引擎转而生成一段"符合世界观的限制"叙事（原文档 16.4 的两个范例就是模板种子）。

降级路径（无 Key）：关键词匹配表把常见意图（跟踪/偷听/搜查/送礼/道歉/挑衅/请教/独处）映射到预设 check，匹配不到则走"通用行动 · 机缘判定"。

### 4.3 narrate 契约

**System prompt**（约 900 token，固定，可缓存）：装载原文档第十六章全文——AI 角色定位、叙事规则、判定规则、边界管理、事件呈现规则。这是文风的地基，逐字照搬。

**User message** 结构：

```
【世界时间】灵元历3701年 九月 第二周 周三 暮
【场景】藏经阁外石阶。暮色，山风，远处灯火次第亮起。
【玩家角色】青玄 · 男 · 18 · 剑渊院学生 · 寒门天才 · 练气五层
  性格：沉稳、赤诚   天赋：过目不忘   灵根：单金灵根
  外貌：（玩家自述）
【在场NPC】温酒酒 · 丹霞院 · 练气六层 · 开朗健谈但藏着自卑
  与你的关系：好感52 信任38 敬畏5 羁绊22（阶段：好感）
  最近互动：周一切磋后她请你喝了酒
【记忆摘要】<滚动摘要 500字>
【最近三回合】<facts 列表>

【本回合已确定发生的事实 —— 必须全部体现，不得增删】
1. 温酒酒收到家中来信，父亲病重
2. 她不愿在你面前哭
3. 你选择了：走过去，在她身旁坐下，不说话
4. 判定结果：圆满
5. 数值变化：温酒酒 好感+12 信任+15 羁绊+8

【本回合结束时必须原样呈现的选项】
A. ...  B. ...  C. ...  D. ...  E. 【自定义行动】

【写作要求】
2000字以上。第二人称"你"。先场景后人物后对话。不要出现任何数字或系统术语。
不要替玩家做决定。不要预告后续剧情。结尾自然过渡到选项前。
```

**硬约束**：`facts` 是不可协商的。prompt 里反复强调"必须全部体现，不得增删"，并在开发期加一个可选的**事实校验**（把生成文本 + facts 丢给便宜模型问"是否全部体现"），线上默认关闭。

### 4.4 上下文压缩

不能把 240 个回合的历史往上堆。策略：

- **状态快照永远全量**（约 600 token）—— 这是模型能保持数值一致的唯一依据
- **最近 3 回合原文 facts**（约 300 token）
- **滚动摘要**：每 8 回合调用一次 `summarize()`，把 8 回合压成 150 字并入总摘要；总摘要超过 600 字时再压一次。始终 ≤ 500 token
- **关系日志**每个 NPC 只带最近 3 条，且只带在场 NPC

总输入稳定在 **2500-3000 token**，与游戏进度无关。这是整个设计里最要紧的一条工程约束。

### 4.5 成本模型

单次叙事：输入 ~2800 token，输出 ~3000 token（2000 汉字）。

| 模型档位 | 单回合成本 | 全程 360 回合 |
|---|---|---|
| 廉价档（DeepSeek / Haiku 级） | ≈ ¥0.012 | ≈ ¥4.3 |
| 中档（Sonnet 级） | ≈ ¥0.14 | ≈ ¥50 |
| 混合策略（推荐） | — | ≈ ¥12 |

**混合策略**：日常事件、修炼、社交小事用廉价模型；心魔关、突破、暗线关键节点、结局、大比决赛用中档模型。在设置里做成两个模型槽 + 一个"重要场景用高级模型"开关。这条要在 UI 里明说，玩家自带 Key 时对成本敏感。

### 4.6 降级策略（无 Key 模式）

必须保证**完整可通关**，不是残废试玩。实现方式是模板文本引擎：每个事件的 outcomes 自带 200-400 字的预写文本，含 `{{player.name}}` `{{npc.name}}` `{{grade}}` 等插槽 + 按 grade 分支的段落。心魔关、突破、结局有专门的模板库。

体感差异：无 Key 约 300 字/回合、文本会重复；有 Key 2000 字/回合、每次都新。这个落差本身就是最好的付费引导（引导玩家去填自己的 Key，不是向你付费）。

## 五、UI 规格

### 5.1 布局

桌面端三栏（左 260px 状态面板 / 中 自适应 主叙事区 / 右 320px 日程与关系）；移动端单栏 + 底部 Tab 切换。断点 768px。

**主叙事区从上到下**：场景图（16:9，顶部 240px，带时段滤镜与轻微 Ken Burns 位移）→ 立绘层（绝对定位，在场 NPC 立绘从场景图底部露出上半身，最多同屏 3 人）→ 叙事文本（打字机效果，可点击跳过，字号 17px 行高 1.9）→ 选项区（竖排卡片，hover 时显示该选项的模糊风险提示）。

### 5.2 视觉基调

呼应美术风格：宣纸底色 `#F5F1E8`，墨色文字 `#2B2B2B`，七院代表色作为强调色（霜白 `#E8EDF2` / 琥珀 `#D9A441` / 靛青 `#2E4A6B` / 翠碧 `#4A8B6F` / 玄紫 `#5B4A7A` / 云灰 `#8C8C8C` / 鹤金 `#C9A961`）。玩家所属学院的代表色作为全局主题色。分隔线用水墨笔触 PNG 而不是 1px 实线。字体：思源宋体 / Noto Serif SC，标题用更重的字重，不用书法字体（可读性差）。

### 5.3 立绘表现

立绘不做全身，做**半身 + 三表情**（平静/情绪/特殊）。切换表情用交叉淡入。说话时该角色立绘亮度 100%、其他 65% + 轻微下移 4px。这是最省成本又最像视觉小说的做法。

### 5.4 时段与天气

**不为每个场景画晨/午/暮三版**，用 CSS 滤镜叠加：晨 `sepia(.15) brightness(1.08) hue-rotate(-8deg)`，午 原图，暮 `sepia(.3) brightness(.88) hue-rotate(-15deg) saturate(1.1)`，夜 `brightness(.55) saturate(.7) hue-rotate(200deg)` + 一层半透明蓝紫遮罩。雨雪雾用 CSS 粒子层。这一条把场景图需求量砍掉了 3/4。

## 七、需要警惕的坑

**数值漂移**：唯一防线是"LLM 不返回数值"。任何时候都不要为了省事让模型返回 `{favor: +10}`。

**上下文膨胀**：滚动摘要必须在 P3 就做，后补会很痛苦。

**事件重复感**：200 个事件在 240 回合里会被抽干。解法是事件**变体化**——同一个事件骨架挂 3-4 组不同 `seed`/`facts`，抽中后再随机选变体，等效扩容到 600+。

**流式中断**：网络断在叙事一半时，引擎状态已经 commit 了。所以 commit 必须在调用 LLM **之前**完成，叙事失败只影响表现，重试即可。

**API Key 安全**：明确提示"仅存本地"，且在代码里不做任何形式的上报。设置页加一个"清除密钥"按钮。

**移动端 2000 字**：手机上 2000 字是很长的滚动。做"分段呈现 + 点击继续"，每段 300-400 字，像视觉小说一样推进。
